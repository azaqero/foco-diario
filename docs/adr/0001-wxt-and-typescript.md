# ADR 0001 — WXT + TypeScript as the extension foundation

- **Status**: accepted
- **Date**: 2026-11-10

## Context

The MVP was a Chrome MV3 extension written in plain JavaScript: a hand-written
`manifest.json`, a single content script and loose CSS. It worked, but there was
no bundling, no types, and no reasonable way to produce Firefox and Edge builds
without duplicating the manifest. The roadmap calls for multi-browser support,
and the code already carries enough logic (extraction, cleaning, rendering) to
justify types and tests.

## Decision

Adopt **WXT** with **TypeScript**.

- File-based entrypoints: `entrypoints/content.ts`, `entrypoints/background.ts`,
  `entrypoints/options/`.
- The manifest is declared in `wxt.config.ts` and generated by WXT at build time.
- `paper.css` is imported from the content script so WXT emits it and adds it to
  the manifest's `css` array.
- Scripts: `dev` (Chrome with HMR), `build` (`wxt build -b chrome`) and `zip`.

WXT was chosen over plain Vite because it solves the per-browser manifest, CSS
injection into content scripts and store packaging in one place.

## Consequences

**Gains**

- One codebase produces Chrome, Edge and Firefox builds.
- TypeScript across the project; `tsc --noEmit` runs in seconds.
- HMR for the content script during development.
- The build step is standard: the output in `.output/` is conventional MV3, so
  there is no runtime dependency on the framework.

**Costs**

- A build step is required before loading the extension (the repo root is no
  longer loaded as an unpacked extension).
- The project depends on WXT for the manifest; a major release may require a
  migration.
- WXT adds `tabs` and `scripting` to the manifest in development mode.

## Alternatives considered

- **Plain JavaScript**: no types, no bundling, and a hand-written manifest per
  browser.
- **Vite + a custom manifest plugin**: more control, but it reimplements what WXT
  already provides (entrypoints, CSS, multi-browser).
- **Plasmo**: more framework and more coupling than a single-content-script
  extension needs.
